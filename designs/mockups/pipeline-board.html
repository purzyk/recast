Recast · design pass · August 2026

A pipeline board built like a ledger

Five status columns, eleven applications, one job: never apply to the same posting twice. The board is the vehicle for the token set — both frames below are the same markup with one palette swapped, so anything that survives the swap is a token and anything that doesn't is a bug. Dark is primary.

01 — Dark, 1440px

The Nomagic card is pinned in its hover state; every other card is live, so hover anywhere. Dates are time-in-column — how long a card has sat where it sits. The ↗ mark appears only when a posting link was saved: Brainly and Tidio have none, which is what makes the mark worth reading.

02 — Light, 1440px

Status hues darken rather than invert — the dark-theme mint and violet land near 2:1 on paper-white. The accent moves the same way: white on amber #E2A03F is 2.0:1, so light gets ochre #A86205 and the button clears 4.8:1. Everything else is the swap doing its job.

03 — What gives first, 1100px

Five columns survive to about 1080px, so the honest answer is that nothing structural gives at 1100 — the columns just compress from 278px to 220px. What gives is padding and metadata, in this order:

  1. 1Top-bar tally drops and the search field collapses to its icon, expanding on focus. The primary action never collapses.
  2. 2Stack padding 12 → 8, card padding 8/12 → 7/8. One step down the spacing scale, never an off-scale value.
  3. 3Role titles truncate to one line with an ellipsis; the full title stays on the detail view. Company never truncates — it's the scan target.
  4. 4Below ~1040px the board scrolls inside itself at a 208px column floor. The board scrolls; the page never scrolls sideways.
  5. 5Nothing collapses columns. A pipeline with a hidden stage is a pipeline you stop trusting — horizontal scroll is the lesser cost.

The accent is amber because every other warm slot on this screen is spoken for — it can't be blue (Applied), green (Offer) or red (Rejected) without the primary action reading as a status. It never appears on a card at rest — the keyboard focus ring is the one exception.

05 — Status

TokenDarkLightSecond cue, carried when hue fails

Hue never works alone. Each status also owns a glyph built from one primitive — a circle, opened, filled, halved, doubled or struck — so the five read apart in greyscale, at 12px, and for anyone who can't separate the blue from the violet. The glyph sits in the column header; the colour repeats as a 2px spine on every card in that column, at 65% until hover. Perceived lightness is laddered too, and after an implementation review the light set was re-spaced to make that literal: dark spans L* 51 → 78, light runs L* 35 → 45 in even ~2.5-point steps. A desaturated screenshot separates all five in either theme. Light can't spread as far — the 4.5:1 floor caps a light value near L* 50 — so the glyph carries proportionally more there. The weakest status is Applied at 4.9:1 on the page ground and 5.3:1 on a card; nothing in the set sits on the threshold.

06 — Spacing, type, borders

Radii and borders
--r-sm · 3px — buttons, inputs, chips
--r-md · 5px — cards, empty states
--bw · 1px — one width, one colour, no shadows anywhere

Two radii, one border width, zero shadows. Depth is done with --surface against --bg and a hairline — which is why the whole thing survives the theme swap without a second set of shadow tokens.

08 — The one risk

    
Columns are fields on a ruled sheet, not floating panels. There are no gutters and
      no column backgrounds — just full-height hairlines and a 2px status rule under each header. It buys
      about 90px of usable card width over the standard tinted-panel kanban and it makes an empty column
      read as an empty field rather than a broken container, which is exactly the problem the Offer
      column has. The cost: the board looks less like Trello, so cards must carry their own borders to
      stay legible as objects. That's the trade — and the review caught where it bites: at
      --border the card edge was a 1.3:1 separation from the card face, fine on a good
      monitor and liable to vanish on a cheap panel or in daylight. Card edges now carry their own
      --border-strong at 1.9:1 while the structural rules stay quiet. If it still fails on a
      second display, the next lever is tinting column headers to --surface, not adding
      gutters.

  


  

    
09 — Handoff notes

    
Decisions from the implementation review, recorded here so the design and the build
      don't drift apart:

    
    
      
  1. 1Status is styleVariants, not a CSS variable.
        The mock sets --stat inline and reads it in children because it is one HTML file.
        The status set is closed and known at build time, so precompile all five and keep it zero-runtime.
        No inline style attributes in the real thing.
    2. 
      
  2. 2Fonts via next/font/google, not a stylesheet link.
        Self-hosted, no render-blocking request, no swap flash.
        The same flash that had to be trimmed out of the portfolio walkthroughs.
    3. 
      
  3. 3Theme needs a pre-hydration inline script.
        createThemeContract plus two createTheme calls gives two class names to
        swap on <html>; applying that from React paints the wrong theme first.
        Read the preference before hydration.
    4. 
      
  4. 4.is-narrow is a demo device. It exists so both widths
        render on one page. Ship it as a media query at the stated breakpoints.
    5. 
      
  5. 5Keep tabular-nums on counts and dates.
        Without it the column counts jitter as they change.
    6. 
      
  6. 6Cards in the frames above are now links, not <article>.
        Keyboard reachable with a 2px accent focus ring; stacks are <ul>/<li> so
        position and count are announced; the ↗ mark carries visually-hidden text instead
        of a title; counts read “3 applications”.
