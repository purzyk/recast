Recast · screens 2–6 · August 2026

The rest of the tool, from the same parts

Five screens and nine components, all assembled from the board's token set. One token was added in the whole pass — --danger, which the destructive button forced — and it deliberately carries the same red as --st-rejected: this tool has one red, and it means “ended badly” in both places. Components are shown in both themes; screens are dark, since the palette contract is already proven.

← the pipeline board and the full token sheet

01 — Components

At 1:1, dark left and light right. Everything here is live — hover the table rows and the document blocks, tab into the fields.

02 — New application

Two panes, because the job description is 90% of the typing and the four fields around it are short. The duplicate guard fires on company + role as you type and shows the record it matched rather than a warning colour — the point isn't “careful”, it's “here's what you already have, do you want that instead?”.

03 — Application detail

Three panes: the record, the source, the output. Status history reuses the board's glyphs as a timeline — the same five marks, read vertically, so the shape of a stalled application is visible without reading a single date.

04 — Tailoring, generating

The call takes seconds, so the wait is narrated rather than spun: named steps that tick over, an elapsed counter, and a 2px sweep on the accent. Under prefers-reduced-motion the sweep stops and the step list carries it alone.

05 — Tailoring, review

The anti-black-box screen. Every generated block names the experience entries it drew from, so you can check the claim before you send it; blocks you touch are marked edited and stop being regenerated. Phrases matched from the job description are underlined in the source pane on the left.

06 — Experience library

Kept current, not imported once — so last edited is a column and used in shows which entries are actually earning their place. Entry text here is placeholder; swap it for yours.

07 — Companies

The screen that answers “have I been here before?” outside the board. Booksy shows two applications and one rejection — exactly the row that should stop you before you apply a third time.

08 — What this pass added

  1. +1--danger, same value as --st-rejected (#C86F63 / #AC4338). Destructive button and field errors. One red, one meaning.
  2. 0No new spacing, radius, or type values. Every screen above is 4/8/12/16/24/40, 3px and 5px, and the seven type steps. If a screen had needed an eighth, that would have been the signal the scale was wrong.
  3. ↓--border-strong earned its keep. Form controls and the loading panel use it too, not just cards. Anything you can click or type into gets the stronger edge; anything structural stays at --border.
  4. ≡One app bar, one screen header, one footer pattern across all five screens. The 52px bar is identical to the board's, so navigation never shifts.

09 — Decisions worth arguing with

Three places where I picked one of two defensible options, so you can overrule them cheaply before they're code:

  1. 1The duplicate guard warns, it doesn't block. You can still add the posting. A hard block would be wrong the day a company reposts a role you genuinely want to re-apply for — but if you'd rather it block on an exact company + role match, that's a one-line change.
  2. 2Generated output saves as a version, not a replacement. The detail screen lists CV v2 and v1. Costs storage and a little UI; buys you the ability to see what you actually sent after a recruiter calls.
  3. 3Status is changed from the detail screen's badge, not by dragging. The board still drags, but the detail view needs its own control, and a select that writes a history entry is simpler than making the badge itself a menu.
